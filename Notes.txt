Security:
- helmet middleware to set headers on every response
- rate limiting for login and register
- session storage (handling token in JS entirely) -> httpOnly cookies

Helmet sets headers like:
    X-Content-Type-Options (prevents MIME sniffing)
    X-Frame-Options (prevents clickjacking)
    Content-Security-Policy (XSS protection layer)

SessionSorage
    Backend returns { token }
    Frontend stores token in sessionStorage
    Axios manually adds Authorization

HttpOnly Cookies
    Backend sets cookie: Set-Cookie: token=...; HttpOnly; Secure
    Browser automatically sends cookie
    Frontend never sees the token

Notes:

HttpOnly cookie (most secure):

Server sets the JWT as an HttpOnly cookie on login. The browser sends it automatically with every request and socket handshake. JavaScript never touches the token at all.

Files: backend/src/routes/auth.js, backend/src/middleware/auth.js, backend/src/sockets/gameSocket.js (read from cookie instead of socket.handshake.auth.token), contexts/webSocket.js (remove auth token from handshake), services/api.js (enable withCredentials), contexts/auth.js (remove token handling entirely)

Tradeoff: Requires CORS credentials: true config and same-site considerations. Most work, but the correct long-term architecture.
